TIPO 1 — PÁGINA WEB (url_conteudo):
  Qualquer URL HTTPS → abre em iframe full-screen na coordenada.
  Sandbox: allow-scripts allow-same-origin allow-forms allow-popups.
  Tela com moldura (barra do COSM no topo).
  Scroll e eventos funcionam normalmente dentro do iframe.

TIPO 2 — OBJETO 3D NATIVO (url_3d):
  Arquivo .glb/.gltf → carregado via GLTFLoader direto na cena Three.js.
  SEM moldura. SEM iframe. O objeto FAZ PARTE do universo.
  Animações tocam automaticamente via AnimationMixer.
  Posição atualizada todo frame via floating origin (coordBase).
  Escala padrão: 500 unidades.
  Usuário hospeda o .glb em qualquer CDN com CORS aberto.

TIPO 3 — CÓDIGO AO VIVO (em desenvolvimento):
  Editor de código dentro do universo.
  Usuário escreve Three.js → objeto aparece no espaço instantaneamente.
  Sem hospedar arquivo. Sem deploy. Roda na engine do COSM.
  Retorna THREE.Object3D → adicionado à cena na posição atual.

  function formatCoord(v) {
    const s = v < 0 ? '-' : '';
    const a = Math.abs(v);
    if (a >= 1e9) return s + (a/1e9).toFixed(2) + 'A'; // Anos-luz
    if (a >= 1e6) return s + (a/1e6).toFixed(2) + 'S'; // Setor

  }

ALOCAÇÃO DE COORDENADAS — server.js
  Pessoas: Esfera de Fibonacci → distribui em X, Y, Z (não espiral 2D)
  Empresas: Eixo X exclusivo (bloco de 1M por empresa)
  GAP = 1.000.000 → espaço enorme, coordenadas embaralhadas (intencional)
  O embaralhamento vem da fórmula Fibonacci, não de aleatoriedade.

  const GAP = 1_000_000;

  function alocarCoordenada(totalPessoas) {
    const i     = totalPessoas;
    const phi   = Math.acos(1 - 2 * (i + 0.5) / 10000);
    const theta = i * 2.39996322972; // ângulo áureo em radianos
    const r     = GAP * Math.sqrt(i + 1);
    return {
      x: Math.round(r * Math.sin(phi) * Math.cos(theta)),
      y: Math.round(r * Math.cos(phi)),
      z: Math.round(r * Math.sin(phi) * Math.sin(theta))
    };
  }

  function alocarCoordenadaEmpresa(n) {
    return { x: (n + 1) * 1_000_000, y: 0, z: 0 };
  }

  pelo espaco sem instalar nada — esse e o momento que converte.

PRE-REQUISITO ANTES DE LANCAR:
  Pelo menos 5 coordenadas com algo genuinamente impressionante.
  A tecnologia ja impressiona sozinha, mas precisa de conteudo
  para mostrar o que e possivel. O resto o boca a boca faz.

VISAO:
  Chat entre coordenadas. Sem numero de telefone, sem email,
  sem nome. Voce e sua coordenada. Ninguem sabe quem e esse numero.

POR QUE E O MAIS SEGURO:
  WhatsApp/Signal/Telegram: precisam de numero de telefone.
  Isso vincula identidade real. O servidor sabe quem fala com quem.
  COSM Chat: voce e COSM://X:Y:Z. Nada mais.

MODELO DE SEGURANCA — 4 camadas:
  1. Sem identidade real — coordenada anonima, sem vinculo com pessoa
  2. Sem descoberta — para te achar precisa da sua coordenada
  3. Autorizacao obrigatoria — mesmo com a coord, entra so se voce aprovar
  4. Criptografia client-side — servidor guarda so texto cifrado, nao le nada

FLUXO DE AUTORIZACAO:
  Coord A quer falar com Coord B
      → B recebe pedido de autorizacao
      → B aprova: chat abre
      → B ignora: Coord A nao existe para B

DEAD DROP DIGITAL — conceito central:
  No mundo real espiao deixa mensagem num local fisico combinado.
  O outro passa la quando puder, pega, deixa resposta.
  Ninguem viu ninguem. Sem rastro de comunicacao direta.
  No COSM e igual — mensagem fica na coordenada esperando.

DOIS MODOS NATURAIS:
  Modo async (principal):
    Mensagem enviada → fica guardada no servidor cifrada
    Destinatario esta offline → nao sabe de nada
    Destinatario entra na coordenada → mensagem aparece
    Sem notificacao, sem push, sem recibo de leitura
    Sem urgencia, sem pressao, sem rastro de horario de atividade

  Modo ao vivo (automatico):
    Duas coordenadas abertas ao mesmo tempo → vira tempo real
    Um PC fecha → volta para async automaticamente
    Sistema detecta sozinho, sem configuracao

POR QUE NAO TEM PUSH NOTIFICATION (e isso e uma vantagem):
  Push precisa de telefone ou email para chegar.
  Isso vincula identidade.
  No COSM nao tem identidade para notificar.
  O silencio e o sigilo.
  So sabe que tem mensagem quando entra na propria coordenada.

PUBLICO IDEAL:
  → Conversas sem pressa e sem urgencia
  → Pessoas que valorizam privacidade real
  → Jornalistas, ativistas, profissionais sigilosos
  → Qualquer um que nao quer ser rastreado por horario de atividade

TECNICO — O QUE PRECISARIA SER CONSTRUIDO:
  Tabela: mensagens (id, coord_origem, coord_destino, conteudo_encrypted,
          enviado_em, lido_em NULL)
  Tabela: autorizacoes (coord_a, coord_b, status, criado_em)
  Modo async: GET simples ao entrar na coordenada busca mensagens nao lidas
  Modo ao vivo: WebSocket quando ambas coordenadas estao ativas
  Sem WebSocket permanente — so ativa quando as duas estao online juntas
