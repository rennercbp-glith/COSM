endereço real e permanente. Funciona como protocolo — como

universo digital tridimensional.

quiser, com endereço próprio, permanente, sem dono central.

O Renner é o fundador do protocolo. Ele fornece a infraestrutura
de coordenadas. Usuários e empresas constroem conteúdo.

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

COMO É GARANTIDO QUE NUNCA DUAS PESSOAS TÊM A MESMA COORD:

1. CONSTRAINT DO BANCO: carteira TEXT UNIQUE — uma carteira = uma coord.
   O banco rejeita duplicata na camada de dados, não só na aplicação.

2. ALOCAÇÃO SEQUENCIAL: a coordenada é calculada com base no COUNT
   de registros existentes. O próximo índice nunca repete porque o
   registro anterior já foi inserido antes.

3. PLANO ANUAL — coordenada nunca volta ao pool automaticamente:
   Quando o plano anual vence (valido_ate < NOW()), o registro PERMANECE
   no banco com status "expirado" implícito. A coordenada continua ocupada.
   Isso é intencional: evita que a coord seja dada para outro enquanto
   o dono pode querer renovar. Futuramente, um job de limpeza pode mover
   coordenadas expiradas há mais de 90 dias para um "pool de renovação"
   — mas isso ainda não existe. Por enquanto, coord anual vencida = bloqueada.

4. RACE CONDITION (risco atual):
   Se dois usuários enviarem pagamento ao mesmo tempo, ambos podem consultar
   COUNT() antes de qualquer um inserir → mesma coordenada gerada.
   Solução futura: SELECT FOR UPDATE ou transação serializable no PostgreSQL.
   Por enquanto: tráfego é baixo, risco é real mas improvável.

REGRA FUNDAMENTAL:
  Uma coordenada alocada = coordenada ocupada para sempre (ou até job futuro).
  Nunca duas coordenadas iguais para carteiras diferentes.
  Nunca a mesma carteira recebe duas coordenadas.

FLOATING ORIGIN (anti-imprecisão):
  Three.js usa float32. A partir de ~1M unidades, objetos tremem.
  Solução: coordBase avança com a câmera.
  Posição real COSM = coordBase + camera.position
  A câmera nunca se afasta muito do zero Three.js.

Para posicionar beacon em coordenada COSM (cx, cy, cz) no espaço 3D:
  beacon.position.set(cx - coordBase.x, cy - coordBase.y, cz - coordBase.z)
  Atualizar todo frame (coordBase muda durante o voo).

ESCALA:
  LOCAL    → 0 a 999 (metros)
  PESSOAL  → 1k a 999k (quilômetros)
  SETOR    → 1S a 999S (setores = milhões)
  ANOS-LUZ → 1A+ (bilhões)

WORMHOLE em 0:0:0:
  Posicionado em -coordBase no espaço Three.js.
  Raio de ejeção: 150 unidades.
  Zona gravitacional: 3000 unidades.
  Ejeção: flash → coordenadas aleatórias 50M-500M unidades.

ALOCAÇÃO ESPIRAL ÁUREA (pessoas):
  theta = n * 2.39996322972  (ângulo áureo)
  r     = 10_000_000 * sqrt(n+1)
  x     = round(r * cos(theta))
  z     = round(r * sin(theta))
  y     = 0

ALOCAÇÃO EMPRESA (prefixo no eixo X):
  Empresa n → x = (n+1) * 1_000_000, y = 0, z = 0
  Empresa 0 → 1.000.000 : 0 : 0
  Empresa 1 → 2.000.000 : 0 : 0

Fluxo completo:
  1. Frontend chama POST /api/pagamento/iniciar
  2. Servidor gera Keypair.generate() → referencia (base58)
  3. Salva pagamento no banco (status: pendente)
  4. Gera URL Solana Pay + QR code
  5. Frontend exibe QR, inicia polling a cada 4s
  6. GET /api/pagamento/verificar/:ref consulta blockchain
  7. getSignaturesForAddress(refPubkey) → se encontrou → confirmado
  8. Servidor registra coordenada automaticamente
  9. Frontend mostra step 3 com a coordenada

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

BUG 1 — Scroll bloqueado nos modais:
  Causa: document.addEventListener('wheel', e => e.preventDefault())
  capturava TODOS os eventos, mesmo com modal aberto.
  Fix: if (modalAberto()) return; antes do preventDefault.
  Lembrar: sempre checar modalAberto() nos event listeners globais.

BUG 2 — Fechar modal exigia reload da página:
  Causa: canvas com pointer-events:auto capturava cliques do backdrop.
  Fix: bloquearCanvas(true) ao abrir modal, bloquearCanvas(false) ao fechar.
  Onclick no backdrop: if (event.target===this) fechar().

BUG 3 — Universo preto, botões sem resposta:
  Causa: const beacons = [] declarado DEPOIS de loop() ser chamado.
  const não é hoisted. ReferenceError matava o render a cada frame.
  Fix: mover TODAS as declarações const de beacons para ANTES do loop().
  Regra: qualquer variável usada dentro de loop() deve ser declarada antes de loop().

BUG 4 — Funções de registro não respondiam (sessão anterior):
  Causa: funções dentro de type="module" não ficam no window.
  onclick="minhaFuncao()" não encontrava.
  Fix: expor todas as funções chamadas por HTML com window.minhaFuncao = function(){}.

    Dois registros simultâneos podem pegar o mesmo COUNT() e gerar
    mesma coordenada. Solução: SELECT FOR UPDATE ou transação serializable.
